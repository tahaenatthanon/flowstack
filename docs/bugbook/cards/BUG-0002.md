# BUG-0002: Email open/click tracking never registers on sent emails

signature: getBaseUrl, app_base_url vs app_public_url, email tracking pixel localhost, opened_at NULL, track-open never hit, นับการเปิด นับการคลิก ไม่ทำงาน
dimension: logic
symptom: "นับการเปิด" / "นับการคลิก" toggles are enabled on the email editor, but after the email is sent and opened, opens/clicks never register — email_tracking.opened_at/clicked_at stay NULL and status stays 'sent' (never 'delivered').
root_cause: getBaseUrl() (api/email-utils.php) read settings key `app_base_url`, but the Admin Mail-settings UI saves the public URL under key `app_public_url` (api/mail-settings.php). `app_base_url` was therefore empty, so getBaseUrl() fell through to the X-Forwarded-Host / HTTP_HOST fallback — which at send time (CLI/cron) is the internal host (localhost/dev). The tracking pixel + click-wrap URLs pointed at an unreachable host, so recipients' mail clients never hit track-open.php / track-click.php.
fix_recipe: In `api/email-utils.php` getBaseUrl(), query both keys preferring the one the admin UI writes: `SELECT value FROM settings WHERE \`key\` IN ('app_public_url','app_base_url') ORDER BY (\`key\`='app_public_url') DESC LIMIT 1`, then rtrim('/'). Keeps legacy `app_base_url` as fallback. (Same key `app_public_url` is already used by api/notification-utils.php.)
regression_test: scripts/test-tracking-baseurl.php — simulates a CLI send context (no HTTP host) and asserts getBaseUrl() resolves to the host of settings.app_public_url instead of localhost. Failed before fix (http://localhost), passes after (https://platform.ktnbs.com/flowstack).
