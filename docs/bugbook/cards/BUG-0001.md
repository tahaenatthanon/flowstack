# BUG-0001: CTA email button loses styling (renders as plain link) after insert

signature: ArticleEditor แทรกปุ่มลิงก์ในอีเมล, tiptap Link mark drops style, email CTA button plain link, email tracking insert
dimension: logic
symptom: User clicks "แทรกปุ่มลิงก์ในอีเมล" to insert a styled CTA button into the email body (rich text). After insertion / save / send, the button renders as a plain text link with no button styling — "insert tracking/button does not work correctly".
root_cause: Tiptap's `Link` mark schema only preserves `href` (plus rel/target/class). The inline `style` attribute on the inserted `<a ... style="display:inline-block;background:#3b82f6;...">` is not in the mark's attribute set, so it is stripped on parse. `editor.getHTML()` therefore emits `<a href>` without styling, and that stripped HTML is what gets saved to `body_html` and sent.
fix_recipe: In `src/components/content/ArticleEditor.tsx`, add a `keepStyleAttribute` helper (`style: { default:null, parseHTML: el => el.getAttribute('style'), renderHTML: a => a.style ? { style:a.style } : {} }`) and apply it via `addAttributes()` to BOTH a `StyledLink = Link.extend(...)` (button look on `<a>`) and a `StyledParagraph = Paragraph.extend(...)` (text-align:center on the wrapping `<p>`). Wire them in: `StarterKit.configure({ link:false, underline:false, paragraph:false })`, then add `StyledParagraph` and `StyledLink.configure({ openOnClick:false })`. Requires dep `@tiptap/extension-paragraph` (match the installed @tiptap version).
regression_test: src/__tests__/content/ctaButtonTracking.test.ts — inserts the CTA markup through the same extension set and asserts the inline button `style` (display:inline-block, padding) survives `getHTML()`. Fails before fix, passes after.
