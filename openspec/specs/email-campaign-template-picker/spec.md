# email-campaign-template-picker Specification

## Purpose

กำหนด layout และพฤติกรรมของส่วน "Template เริ่มต้น" ในไดอะล็อกสร้าง/แก้ไขแคมเปญอีเมล (`MarketingPage.tsx`) — ตำแหน่งเป็น section เต็มความกว้างแยกจากการ์ด "ผู้รับ" แสดงตัวเลือกทั้งหมดโดยไม่ต้องเลื่อน และพฤติกรรม toggle เลือก/ยกเลิกการเลือกพร้อม confirm dialog ก่อนล้างเนื้อหาอีเมล

## Requirements

### Requirement: Template เริ่มต้น จัดวางเป็น section เดี่ยวเต็มความกว้าง ไม่ต้อง scroll
ไดอะล็อกสร้าง/แก้ไขแคมเปญอีเมล SHALL แสดงตัวเลือก "Template เริ่มต้น" เป็น section แยกต่างหาก อยู่นอกการ์ด "ผู้รับ" กินความกว้างเต็มไดอะล็อก และแสดงตัวเลือกทั้งหมดพร้อมกันแบบห่อบรรทัด (wrap) โดยไม่ต้องเลื่อนแนวนอนเพื่อดูตัวเลือกที่เหลือ

#### Scenario: เห็น template ครบทุกตัวโดยไม่ต้อง scroll
- **WHEN** ไดอะล็อกสร้าง/แก้ไขแคมเปญ render ส่วน "Template เริ่มต้น"
- **THEN** ปุ่มเลือก template ทุกตัวถูกแสดงพร้อมกัน ห่อขึ้นบรรทัดใหม่เมื่อไม่พอความกว้าง แทนการเลื่อนแนวนอน

#### Scenario: ไม่ล้นออกนอกขอบไดอะล็อกไม่ว่าความกว้างจอเท่าใด
- **WHEN** ไดอะล็อกแสดงผลบนความกว้างหน้าจอใดก็ตาม (รวมความกว้างแคบ)
- **THEN** ส่วน "Template เริ่มต้น" ไม่ล้นออกนอกขอบไดอะล็อก (ไม่มีเนื้อหาส่วนใดถูกตัดหรือแสดงเกินขอบ)

#### Scenario: การ์ด "ผู้รับ" ไม่มี Template เริ่มต้น ซ้อนอยู่อีกต่อไป
- **WHEN** ผู้ใช้ดูการ์ด "ผู้รับ" ใน grid ผู้ส่ง/ผู้รับ
- **THEN** การ์ดแสดงเฉพาะตัวเลือกกลุ่มผู้รับและจำนวนผู้รับที่จะส่งถึง ไม่มีตัวเลือก template ซ้อนอยู่ในการ์ดนี้

### Requirement: เลือก Template ซ้ำเพื่อยกเลิกการเลือก (toggle)
ปุ่มเลือก template SHALL ทำงานแบบ toggle: คลิก template ที่ยังไม่ถูกเลือก = เลือก template นั้นทันที (นำเนื้อหามาแทนที่เนื้อหาอีเมลปัจจุบัน) คลิก template ที่ถูกเลือกอยู่แล้วซ้ำอีกครั้ง = เข้าสู่กระบวนการยกเลิกการเลือก

#### Scenario: คลิกเลือก template ที่ยังไม่ได้เลือก
- **WHEN** ผู้ใช้คลิก template ที่ยังไม่ถูกเลือกอยู่ (ไม่ว่าจะยังไม่มี template ใดถูกเลือก หรือมี template อื่นถูกเลือกอยู่ก่อน)
- **THEN** template นั้นกลายเป็น template ที่ถูกเลือก และเนื้อหาอีเมล (`campaignBody`) ถูกแทนที่ด้วย HTML ของ template นั้นทันที โดยไม่ต้องยืนยัน

#### Scenario: คลิกซ้ำ template ที่เลือกอยู่
- **WHEN** ผู้ใช้คลิก template ที่กำลังถูกเลือกอยู่ (`selectedTemplate` ตรงกับ template ที่คลิก) ซ้ำอีกครั้ง
- **THEN** ระบบเริ่มกระบวนการยกเลิกการเลือก (ตาม Requirement "ยืนยันก่อนล้างเนื้อหาเมื่อยกเลิกการเลือก Template") แทนที่จะเลือกซ้ำเฉยๆ

### Requirement: ยืนยันก่อนล้างเนื้อหาเมื่อยกเลิกการเลือก Template
เมื่อผู้ใช้ยกเลิกการเลือก template (คลิกซ้ำ template ที่เลือกอยู่) ระบบ SHALL แสดง confirm dialog ก่อนล้างเนื้อหาอีเมลเสมอ — หากผู้ใช้ยืนยัน ให้ล้าง `selectedTemplate` และ `campaignBody` กลับเป็นค่าว่าง หากผู้ใช้ยกเลิก ให้คงสถานะเดิมไว้ทั้งหมด (ไม่เปลี่ยนแปลงอะไร)

#### Scenario: ยืนยันการยกเลิกเลือก → ล้างเนื้อหา
- **WHEN** ผู้ใช้คลิกซ้ำ template ที่เลือกอยู่ แล้วกดยืนยันใน confirm dialog
- **THEN** `selectedTemplate` ถูกล้างกลับเป็นค่าว่าง และเนื้อหาอีเมล (`campaignBody`) ถูกล้างกลับเป็นค่าว่างเช่นกัน

#### Scenario: ยกเลิกที่ confirm dialog → ไม่มีอะไรเปลี่ยน
- **WHEN** ผู้ใช้คลิกซ้ำ template ที่เลือกอยู่ แล้วกดยกเลิกใน confirm dialog (หรือปิด dialog โดยไม่ยืนยัน)
- **THEN** `selectedTemplate` ยังคงเป็น template เดิม และเนื้อหาอีเมล (`campaignBody`) ไม่ถูกแก้ไข

### Requirement: เนื้อหาที่ตั้งค่าจาก Template ต้องไม่ถูกแก้ไขเพิ่มเติมโดยอัตโนมัติ
เมื่อเลือก template แล้วเนื้อหาอีเมล (`campaignBody`) ถูกตั้งค่าเป็น HTML ของ template นั้น ระบบ SHALL คงเนื้อหานั้นไว้ตรงตามต้นฉบับ (ไม่มีการแก้ไข/ตัดทอนสไตล์เพิ่มเติมโดยอัตโนมัติ) จนกว่าผู้ใช้จะแก้ไขเนื้อหาเองจริงๆ ผ่านการพิมพ์ในตัวแก้ไข

#### Scenario: เนื้อหายังตรงกับ template หลังเลือกโดยไม่ได้แก้ไขอะไร
- **WHEN** ผู้ใช้เลือก template ที่มีสไตล์กำหนดเอง (เช่น สีพื้นหลัง) แล้วไม่ได้พิมพ์แก้ไขอะไรต่อ
- **THEN** เนื้อหาอีเมล (`campaignBody`) ที่จะถูกบันทึกหรือส่งยังคงมีสไตล์ครบตามต้นฉบับของ template นั้น ไม่ถูกตัดทอนออกไป

#### Scenario: แท็บตัวอย่างแสดงตรงกับ template ที่เลือก
- **WHEN** ผู้ใช้เลือก template แล้วเปิดแท็บ "ตัวอย่าง" ของไดอะล็อกสร้าง/แก้ไขแคมเปญ
- **THEN** ตัวอย่างที่แสดงตรงกับรูปแบบของ template นั้นตามที่เห็นในแท็บ Template (สีพื้นหลังและสไตล์อื่นๆ ครบถ้วน)
