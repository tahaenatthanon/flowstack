# approval-dialog-sizing Specification

## Purpose

กำหนดความกว้างและขนาดโดยรวมของ popup "ยืนยันการอนุมัติ", "ขอแก้ไขเนื้อหา" และ "ปฏิเสธเนื้อหา" ให้เป็นมาตรฐานเดียวกัน เพื่อให้ UI มีความสม่ำเสมอและเป็นระเบียบ และปรับช่องกรอกเหตุผลให้ปรับความสูงอัตโนมัติตามเนื้อหา

## Requirements

### Requirement: ขนาด popup ทั้งสามเท่ากัน
popup "ยืนยันการอนุมัติ", "ขอแก้ไขเนื้อหา" และ "ปฏิเสธเนื้อหา" SHALL ใช้ความกว้างมาตรฐานเดียวกันบนจอ desktop และเต็มจอบนมือถือ

#### Scenario: ความกว้างบน desktop
- **WHEN** ผู้ใช้เปิด popup ใดในสาม popup บน viewport แบบ desktop (`sm` ขึ้นไป)
- **THEN** dialog ใช้ความกว้างสูงสุด `sm:max-w-md` (448px) เท่ากันทั้งสาม

#### Scenario: ความกว้างบนมือถือ
- **WHEN** ผู้ใช้เปิด popup ใดในสาม popup บน viewport แบบมือถือ
- **THEN** dialog กินความกว้างเต็มจอ (`w-full`)

### Requirement: popup ไม่กว้างเกินความจำเป็น
popup ทั้งสาม SHALL มีขนาดพอดีกับเนื้อหา โดยไม่กว้างจนเกินความจำเป็น

#### Scenario: ยืนยันการอนุมัติ
- **WHEN** ผู้ใช้เปิด popup "ยืนยันการอนุมัติ"
- **THEN** dialog มีความกว้างพอดีกับข้อความยืนยันและปุ่ม ไม่กว้างเกือบเต็มจอ

#### Scenario: ขอแก้ไขเนื้อหา / ปฏิเสธเนื้อหา
- **WHEN** ผู้ใช้เปิด popup "ขอแก้ไขเนื้อหา" หรือ "ปฏิเสธเนื้อหา"
- **THEN** dialog มีความกว้างพอดีกับ description และ textarea เหตุผล ไม่กว้างเกินความจำเป็น

### Requirement: Layout ภายในเหมาะสมกับเนื้อหา
popup ทั้งสาม SHALL คงโครงสร้าง Layout ภายในเดิมที่เหมาะสมกับเนื้อหาของแต่ละ popup

#### Scenario: โครงสร้างภายในคงเดิม
- **WHEN** ผู้ใช้เปิด popup ใดในสาม popup
- **THEN** header (title + description), เนื้อหากลาง (เฉพาะ reason dialog มี textarea เหตุผล), และ footer (ปุ่มยกเลิก/ยืนยัน) ยังคงอยู่ครบและจัดวางเหมือนเดิม

### Requirement: ช่องกรอกเหตุผลปรับความสูงอัตโนมัติ
ช่องกรอกเหตุผล (textarea) ใน popup "ขอแก้ไขเนื้อหา" และ "ปฏิเสธเนื้อหา" SHALL ปรับความสูงตามจำนวนบรรทัดของข้อความที่กรอกโดยอัตโนมัติ

#### Scenario: ขยายเมื่อข้อความมีหลายบรรทัด
- **WHEN** ผู้ใช้กรอกข้อความที่มีหลายบรรทัดในช่องเหตุผล
- **THEN** ช่องกรอกขยายความสูงอัตโนมัติเพื่อแสดงข้อความครบถ้วนโดยไม่มี scrollbar ภายใน

#### Scenario: ลดความสูงเมื่อข้อความสั้นลง
- **WHEN** ผู้ใช้ลบข้อความจนเหลือบรรทัดน้อยลง
- **THEN** ช่องกรอกลดความสูงลงอัตโนมัติตามเนื้อหา

#### Scenario: ความสูงขั้นต่ำคงเดิม
- **WHEN** ผู้ใช้เปิด popup และยังไม่ได้กรอกเหตุผล
- **THEN** ช่องกรอกมีความสูงขั้นต่ำเท่ากับเดิม (min-height) และไม่แคบกว่าเดิม

### Requirement: พฤติกรรมเดิมคงอยู่
การปรับขนาด SHALL ไม่เปลี่ยนแปลงการทำงานเดิมของการอนุมัติ/ขอแก้ไข/ปฏิเสธ

#### Scenario: ฟังก์ชันเดิมยังทำงาน
- **WHEN** ผู้ใช้กดปุ่มยืนยันในแต่ละ popup
- **THEN** ระบบยังคงเรียก logic เดิม (อนุมัติ, ขอแก้ไข, ปฏิเสธ) พร้อมเหตุผล (ไม่บังคับ) เช่นเดิม
