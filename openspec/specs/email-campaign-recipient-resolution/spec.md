# email-campaign-recipient-resolution Specification

## Purpose

กำหนดวิธี resolve รายชื่อผู้รับของแคมเปญอีเมล (`api/email-campaigns.php`) เมื่อแคมเปญหนึ่งผูกกับหลายกลุ่มผู้รับ (`email_groups`) พร้อมกัน — ครอบคลุมการเลือกหลายกลุ่มผ่าน UI, การ dedupe ผู้รับตามอีเมล (ไม่ใช่ `customer_id`, เพราะอีเมลเดียวกันเป็น contact ของหลายบริษัทได้), กติกาเลือกแถวสำหรับ personalization เมื่อมีความกำกวม, และ endpoint สำหรับ preview จำนวนผู้รับแบบ live ก่อนบันทึกแคมเปญ

## Requirements

### Requirement: เลือกผู้รับแคมเปญได้หลายกลุ่มพร้อมกัน
หน้าแก้ไข/สร้างแคมเปญ SHALL ให้ผู้ใช้เลือก "กลุ่มผู้รับ" ได้มากกว่า 1 กลุ่มพร้อมกันผ่าน `MultiSelectCombobox` (dropdown ค้นหาได้ พร้อม chip แสดงกลุ่มที่เลือกไว้) — แทนที่ checkbox list เดิม โดยแสดงชื่อกลุ่มและจำนวนสมาชิก (`member_count`) เป็นข้อความรองของแต่ละตัวเลือก

#### Scenario: เลือกได้หลายกลุ่ม
- **WHEN** ผู้ใช้เลือกกลุ่มผู้รับมากกว่า 1 กลุ่มผ่าน `MultiSelectCombobox`
- **THEN** ทุกกลุ่มที่เลือกไว้ถูกบันทึกเป็น `group_ids` ของแคมเปญ ไม่ถูกจำกัดเหลือกลุ่มเดียว

#### Scenario: แสดงจำนวนสมาชิกต่อกลุ่ม
- **WHEN** popover ของกลุ่มผู้รับ render
- **THEN** แต่ละกลุ่มแสดงชื่อกลุ่มและจำนวนสมาชิก (`member_count`) กำกับไว้เป็นข้อความรอง

#### Scenario: ค้นหากลุ่มผู้รับได้
- **WHEN** ผู้ใช้พิมพ์ค้นหาชื่อกลุ่มใน `MultiSelectCombobox`
- **THEN** รายการกลุ่มที่ไม่ตรงกับคำค้นหาถูกซ่อนไป

#### Scenario: เห็นกลุ่มที่เลือกไว้เป็น chip
- **WHEN** ผู้ใช้เลือกกลุ่มผู้รับไว้แล้วอย่างน้อย 1 กลุ่ม
- **THEN** เห็นชื่อกลุ่มที่เลือกไว้เป็น chip นอก popover พร้อมเอาออกได้ทันทีโดยไม่ต้องเปิด popover ใหม่

### Requirement: ผู้รับที่ resolve จากหลายกลุ่มต้อง dedupe ตามอีเมล ไม่ใช่ customer_id
ระบบ SHALL คำนวณรายชื่อผู้รับสุดท้ายของแคมเปญ (ตอนบันทึกแคมเปญ, ตอน preview, และตอนส่งจริง) โดย dedupe ตามอีเมล (normalize ด้วย lowercase + trim) ไม่ใช่ตาม `customer_id` — เพราะอีเมลเดียวกันสามารถเป็น `customers` คนละแถวได้เมื่อเป็น contact ของหลายบริษัท (unique key คือ `(company_id, email)` ไม่ใช่ `email` เดี่ยวๆ)

#### Scenario: อีเมลเดียวกันข้ามบริษัทนับเป็นคนเดียว
- **WHEN** อีเมลเดียวกันปรากฏเป็น `customers` มากกว่า 1 แถว (คนละ `company_id`) และทั้งสองแถวอยู่ในกลุ่มที่ถูกเลือกไว้ของแคมเปญเดียวกัน (ไม่ว่าจะกลุ่มเดียวกันหรือคนละกลุ่ม)
- **THEN** ผู้รับคนนั้นถูกนับและส่งถึงเพียง **ครั้งเดียว** ไม่ใช่ 1 ครั้งต่อแถว

#### Scenario: เลือกแถวสำหรับ personalization ด้วยกติกาคงที่
- **WHEN** อีเมลเดียวกันมีมากกว่า 1 แถวใน `customers` ที่ต้อง dedupe เหลือแถวเดียว
- **THEN** ระบบเลือกแถวที่ `is_primary_contact = 1` เป็นอันดับแรก หากไม่มีแถวใดเป็น primary contact (หรือมีมากกว่าหนึ่งแถว) ให้ใช้แถวที่มี `updated_at` ล่าสุดแทน

#### Scenario: การเปรียบเทียบอีเมลไม่สนตัวพิมพ์ใหญ่เล็กและช่องว่าง
- **WHEN** อีเมลของสองแถวต่างกันแค่ตัวพิมพ์ใหญ่/เล็กหรือช่องว่างนำหน้า-ต่อท้าย (เช่น `A@x.com` และ `a@x.com `)
- **THEN** ทั้งสองแถวถูกมองว่าเป็นอีเมลเดียวกันและ dedupe รวมกัน

### Requirement: จำนวนผู้รับต้องตรงกันทั้ง 3 จุด (preview, บันทึก, ส่งจริง)
ระบบ SHALL ใช้ฟังก์ชัน resolve ผู้รับร่วมกันจุดเดียว (`resolveCampaignRecipients`) สำหรับทั้ง 3 จุดที่ต้องรู้จำนวน/รายชื่อผู้รับ: endpoint preview, การบันทึก `total_recipients` ตอนสร้าง/แก้ไขแคมเปญ, และการส่งจริงใน `sendCampaign()` — ห้ามมี query คำนวณผู้รับแยกกันคนละสูตรอีก

#### Scenario: ตัวเลข preview ตรงกับตอนบันทึก
- **WHEN** ผู้ใช้เลือกชุดกลุ่มผู้รับชุดหนึ่ง แล้วดูตัวเลข preview ก่อนกดบันทึก จากนั้นกดบันทึกแคมเปญด้วยชุดกลุ่มเดียวกัน
- **THEN** ตัวเลข preview เท่ากับ `total_recipients` ที่ถูกบันทึกลงฐานข้อมูล

#### Scenario: ตัวเลขที่บันทึกตรงกับจำนวนที่ส่งจริง
- **WHEN** แคมเปญที่มี `total_recipients` = N ถูกกดส่ง และไม่มีผู้รับคนใดถูกลบ/ปิดใช้งานระหว่างนั้น
- **THEN** จำนวนอีเมลที่ส่งสำเร็จรวมกับที่ส่งล้มเหลว (`sent + failed`) เท่ากับ N

### Requirement: Endpoint แสดงจำนวนผู้รับแบบ live ก่อนบันทึกแคมเปญ
ระบบ SHALL มี `GET /email-campaigns.php?action=recipient_count&group_ids=<csv>` ที่คืนจำนวนผู้รับที่ dedupe แล้ว (ตามกติกาด้านบน) จากชุด `group_ids` ที่ส่งมา โดยไม่ต้องมีแคมเปญอยู่จริงในระบบก่อน (ใช้ตอนกำลังสร้างแคมเปญใหม่ได้)

#### Scenario: คืนจำนวนผู้รับที่ dedupe แล้ว
- **WHEN** เรียก `?action=recipient_count&group_ids=g1,g2`
- **THEN** คืน JSON `{ "count": N }` โดย N คือจำนวนอีเมลไม่ซ้ำหลัง resolve ผู้รับจากกลุ่ม g1 และ g2 รวมกัน

#### Scenario: ไม่ส่ง group_ids คืนศูนย์
- **WHEN** เรียก `?action=recipient_count` โดยไม่มี `group_ids` หรือเป็นค่าว่าง
- **THEN** คืน `{ "count": 0 }` (ไม่ error)

### Requirement: UI แสดงตัวเลขผู้รับแบบ live ระหว่างเลือกกลุ่ม
หน้าแก้ไข/สร้างแคมเปญ SHALL แสดงข้อความ "จะส่งถึง N คน" ที่อัปเดตทุกครั้งที่ผู้ใช้ติ๊ก/ยกเลิกกลุ่มผู้รับ โดยเรียก endpoint `recipient_count` (debounce ป้องกันยิงถี่เกินตอนติ๊กหลายครั้งเร็วๆ) แทนการบวก `member_count` ของแต่ละกลุ่มดิบๆ ฝั่ง client

#### Scenario: ตัวเลขอัปเดตตามกลุ่มที่เลือก
- **WHEN** ผู้ใช้ติ๊ก/ยกเลิกกลุ่มผู้รับ
- **THEN** ข้อความจำนวนผู้รับอัปเดตเป็นค่าจาก endpoint `recipient_count` ของชุดกลุ่มที่เลือกอยู่ปัจจุบัน (ไม่ใช่ผลรวม `member_count` แบบดิบ)

#### Scenario: ไม่เลือกกลุ่มเลยไม่แสดงตัวเลข
- **WHEN** ยังไม่มีกลุ่มผู้รับใดถูกเลือก
- **THEN** ไม่แสดงข้อความจำนวนผู้รับ (หรือแสดง 0 อย่างชัดเจนว่ายังไม่ได้เลือก)
