# send-schedule-dialog-sizing Specification

## Purpose

กำหนดขนาดและพฤติกรรมการเลื่อน (scroll) ของ popup "ส่งเดี๋ยวนี้" และ "ตั้งเวลาโพสต์" (`SchedulePublishDialog`) ให้พอดีกับเนื้อหาภายในทั้งสองโหมด โดยหัวข้อและปุ่ม footer คงอยู่กับที่เสมอ

## ADDED Requirements

### Requirement: ความกว้างของ popup พอดีกับเนื้อหา
popup "ส่งเดี๋ยวนี้" และ "ตั้งเวลาโพสต์" SHALL ใช้ความกว้างที่กว้างขึ้นและพอดีกับเนื้อหาภายในบนจอ desktop และเต็มจอบนมือถือ

#### Scenario: ความกว้างบน desktop
- **WHEN** ผู้ใช้เปิด popup บน viewport แบบ desktop (`sm` ขึ้นไป)
- **THEN** dialog ใช้ความกว้างสูงสุด `sm:max-w-xl` (576px)

#### Scenario: ความกว้างบนมือถือ
- **WHEN** ผู้ใช้เปิด popup บน viewport แบบมือถือ
- **THEN** dialog กินความกว้างเต็มจอ (`w-full`)

### Requirement: เฉพาะรายการ channel เท่านั้นที่เลื่อน
เมื่อรายการ channel ยาวเกินพื้นที่แสดง ระบบ SHALL เลื่อนเฉพาะส่วนรายการ channel ไม่ใช่เลื่อนทั้ง dialog

#### Scenario: มี channel จำนวนมาก
- **WHEN** มี channel ที่ใช้งานอยู่มากจนเกินความสูงที่กำหนด
- **THEN** เฉพาะพื้นที่เนื้อหา (รายการ channel และฟิลด์เนื้อหา) ที่เลื่อน (`overflow-y-auto`)
- **AND** หัวข้อ (`DialogHeader`) และปุ่ม footer (`DialogFooter`) ยังคงมองเห็นและเข้าถึงได้

#### Scenario: มี channel น้อย
- **WHEN** มี channel น้อยและเนื้อหาไม่เกินความสูงที่กำหนด
- **THEN** dialog ย่อขนาดให้พอดีกับเนื้อหาโดยไม่เกิด scrollbar ที่ไม่จำเป็น

### Requirement: ขนาดแยกตามโหมด
โหมด "ส่งเดี๋ยวนี้" SHALL ใช้พื้นที่น้อยกว่าโหมด "ตั้งเวลาโพสต์" เนื่องจากไม่มีช่องวันที่/เวลา

#### Scenario: โหมดส่งเดี๋ยวนี้
- **WHEN** ผู้ใช้เปิด popup ในโหมด `send_now`
- **THEN** dialog ไม่แสดงช่องวันที่/เวลา และมีความสูงพอดีกับเนื้อหาที่เหลือ (รายการ channel + ฟิลด์เนื้อหาตามที่เลือก)

#### Scenario: โหมดตั้งเวลาโพสต์
- **WHEN** ผู้ใช้เปิด popup ในโหมด `schedule`
- **THEN** dialog แสดงช่องวันที่/เวลาเพิ่มเติม และเนื้อหายังคงถูกจำกัดการเลื่อนตาม Requirement ก่อนหน้า

### Requirement: ระยะห่างและการจัดวางภายใน popup
popup SHALL มีระยะห่างและการจัดวางภายในที่เหมาะสม เพื่อให้เนื้อหาดูเป็นระเบียบและใช้งานง่าย

#### Scenario: ระยะห่างระหว่าง section
- **WHEN** ผู้ใช้เปิด popup
- **THEN** ระยะห่างแนวตั้งระหว่าง section (รายการ channel, ฟิลด์เนื้อหา, ช่องวันที่/เวลา) สม่ำเสมอ
- **AND** แถว channel มี padding ที่เพียงพอต่อการอ่านและแตะ/คลิก

#### Scenario: การจัดวางหัวข้อและ footer สอดคล้องกับความกว้างใหม่
- **WHEN** ผู้ใช้เปิด popup
- **THEN** หัวข้อ (`DialogHeader`) และปุ่ม footer (`DialogFooter`) จัดวางได้สอดคล้องกับความกว้างใหม่โดยไม่แน่นเกินไป

### Requirement: พฤติกรรมเดิมคงอยู่
การปรับขนาด SHALL ไม่เปลี่ยนแปลงการทำงานเดิมของการส่ง/ตั้งเวลา

#### Scenario: ส่งและตั้งเวลายังทำงานเหมือนเดิม
- **WHEN** ผู้ใช้เลือก channel และกดปุ่มยืนยัน
- **THEN** ระบบยังคงเรียก `useSendNow` (โหมด send_now) หรือ `useScheduleContent` (โหมด schedule) เช่นเดิม พร้อม validation และ toast ตามเดิม
