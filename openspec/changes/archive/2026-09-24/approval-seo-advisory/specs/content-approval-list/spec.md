## REMOVED Requirements

### Requirement: User can approve a content item
**Reason**: การอนุมัติย้ายไปทำได้จากหน้ารายละเอียดเนื้อหาเท่านั้น (คลิกแถว → เปิดดู → กดอนุมัติ) — ไม่มีปุ่มอนุมัติที่แถวตารางอีกต่อไป พฤติกรรมการอนุมัติ (เปลี่ยนสถานะเป็น `approved`) อธิบายไว้ที่ capability `approval-detail-actions` แล้ว
**Migration**: ไม่มีข้อมูลต้องย้าย — ตารางรายการอนุมัติยังคลิกแถวเพื่อเปิดดูรายละเอียดได้ตามเดิม

### Requirement: User can reject a content item
**Reason**: การปฏิเสธย้ายไปทำได้จากหน้ารายละเอียดเนื้อหาเท่านั้น เหมือนการอนุมัติ — อธิบายไว้ที่ capability `approval-detail-actions` แล้ว
**Migration**: การบันทึก `reject_reason` ยังทำงานเหมือนเดิม (ดู requirement "Content items store reject reason" ที่ไม่เปลี่ยน)

### Requirement: User can request revision from approval list
**Reason**: การขอแก้ไขย้ายไปทำได้จากหน้ารายละเอียดเนื้อหาเท่านั้น รวมถึง scenario "Three approval actions available" ที่อธิบายคอลัมน์ "จัดการ" ซึ่งถูกตัดออกทั้งคอลัมน์
**Migration**: การบันทึก `reject_reason` ตอนขอแก้ไขยังทำงานเหมือนเดิม (ดู requirement "Revision items store reason" ที่ไม่เปลี่ยน)

### Requirement: Manage column keeps fixed width
**Reason**: คอลัมน์ "จัดการ" ถูกตัดออกจากตารางทั้งคอลัมน์ (ไม่ใช่แค่ปุ่มในนั้น) — การอนุมัติ/ขอแก้ไข/ปฏิเสธ ทำได้จากหน้ารายละเอียดเท่านั้น ไม่มีคอลัมน์นี้ให้ล็อกความกว้างอีกต่อไป
**Migration**: ตารางเหลือ 6 คอลัมน์ (ชื่อคอนเทนต์, ประเภท, แพลตฟอร์ม, วันที่สร้าง, วันที่ขออนุมัติ, สถานะ) ไม่มีคอลัมน์ action

## ADDED Requirements

### Requirement: แถวตารางไม่มีปุ่มจัดการ — เปิดดูรายละเอียดเพื่อดำเนินการเท่านั้น
ตารางรายการอนุมัติ SHALL ไม่มีคอลัมน์หรือปุ่มสำหรับอนุมัติ/ขอแก้ไข/ปฏิเสธที่ตัวแถวเลย — การคลิกที่แถวใดก็ตาม SHALL เปิดหน้ารายละเอียดเนื้อหาเท่านั้น (`ContentDetailView` ที่ `context='approval'`) ซึ่งเป็นที่เดียวที่มีปุ่มดำเนินการ

#### Scenario: ตารางไม่มีคอลัมน์จัดการ
- **WHEN** ผู้ใช้เปิด Tab "รายการอนุมัติ"
- **THEN** ตารางแสดงเฉพาะคอลัมน์ ชื่อคอนเทนต์, ประเภท, แพลตฟอร์ม, วันที่สร้าง, วันที่ขออนุมัติ, สถานะ — ไม่มีคอลัมน์ "จัดการ" หรือปุ่มอนุมัติ/ขอแก้ไข/ปฏิเสธที่แถว

#### Scenario: คลิกแถวเปิดหน้ารายละเอียดเสมอ
- **WHEN** ผู้ใช้คลิกที่แถวใดก็ตามในตาราง ไม่ว่าสถานะจะเป็นอะไร
- **THEN** ระบบเปิดหน้ารายละเอียดเนื้อหาของรายการนั้น

#### Scenario: อนุมัติ/ขอแก้ไข/ปฏิเสธ ทำได้จากหน้ารายละเอียดเท่านั้น
- **WHEN** ผู้ใช้ต้องการอนุมัติ ขอแก้ไข หรือปฏิเสธ content item ที่สถานะ `pending_approval`
- **THEN** ผู้ใช้ต้องเปิดหน้ารายละเอียดก่อนเสมอ (ไม่มีทางลัดกดจากตาราง) แล้วดำเนินการที่ปุ่มในหน้ารายละเอียดตามที่ระบุไว้ใน capability `approval-detail-actions`
