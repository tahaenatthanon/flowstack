## Context

Sidebar ของแอปถูกกำหนดใน `src/components/AppSidebar.tsx` ผ่าน array `NAV_GROUPS: NavGroup[]` โดยแต่ละกลุ่ม (`NavGroup`) มี `items: NavItem[]` ซึ่ง render เรียงตามลำดับใน array ตามลำดับที่ประกาศ

กลุ่ม "การตลาด" (`key: 'marketing'`) ปัจจุบันมี 6 รายการเรียงลำดับดังนี้: แดชบอร์ดคอนเทนต์ → แคมเปญอีเมล → คอนเทนต์โซเชียล → ปฏิทินคอนเทนต์ → วิเคราะห์แคมเปญ → สตูดิโอสื่อ

## Goals / Non-Goals

**Goals:**
- จัดเรียงลำดับรายการในกลุ่ม "การตลาด" ใหม่ให้สอดคล้องกับ workflow ใช้งานจริง (แดชบอร์ด → ผลิตคอนเทนต์ → วางแผน → แคมเปญ → วิเคราะห์ → สร้างสื่อ)

**Non-Goals:**
- ไม่เปลี่ยนแปลง Route/`href`, ไอคอน, `menuKey`, หรือ permission ของแต่ละเมนู
- ไม่เปลี่ยนแปลงโครงสร้าง/ลำดับของกลุ่มเมนูอื่น
- ไม่เพิ่ม/ลบเมนูใด ๆ

## Decisions

- **แก้เฉพาะลำดับ items ใน array** — เรียง `items` ของกลุ่ม `marketing` ใหม่โดยคง property อื่นของแต่ละ item ไว้ครบ เนื่องจากลำดับการ render ของ Sidebar ถูกกำหนดโดยลำดับใน array อยู่แล้ว จึงไม่ต้องเพิ่มกลไก sort ใหม่ใด ๆ

ลำดับใหม่:
1. แดชบอร์ดคอนเทนต์ (`/content-dashboard`)
2. คอนเทนต์โซเชียล (`/content`)
3. ปฏิทินคอนเทนต์ (`/content-planner`)
4. แคมเปญอีเมล (`/marketing`)
5. วิเคราะห์แคมเปญ (`/campaign-analytics`)
6. สตูดิโอสื่อ (`/media-studio`)

- **ไม่ใช้ทางเลือกอื่น** เช่น เพิ่มฟิลด์ `order` หรือกลไก sort แยก — overkill สำหรับการเรียงลำดับ static ที่ใช้ที่เดียว

## Risks / Trade-offs

- [ผู้ใช้ที่คุ้นเคยกับตำแหน่งเมนูเดิมอาจต้องปรับตัว] → การเปลี่ยนแปลงเล็กน้อยและลำดับใหม่ไล่ตาม workflow ทำให้เข้าใจง่ายขึ้น
- [ความเสี่ยงการแก้ array ผิดตำแหน่ง] → แก้เฉพาะกลุ่ม `marketing` โดย property อื่นคงเดิม และผ่าน `pnpm lint`/`pnpm build` ตรวจสอบ
