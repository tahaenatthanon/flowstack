## Context

`MarketingPage.tsx` (`/marketing`) และ `AttributionTab.tsx` (แท็บย่อยในหน้าเดียวกัน) มีข้อความภาษาอังกฤษหลุดอยู่จำนวนมาก ตรวจพบระหว่างสำรวจโค้ดในรอบก่อนหน้า (การตัดแท็บ "รายงาน" ที่ซ้ำซ้อนออกจากหน้าเดียวกัน) `AttributionTab.tsx` มีขอบเขตอังกฤษหลุดมากกว่าที่คาดไว้แต่แรกมาก — ไม่ใช่แค่หัวตารางแต่รวมถึงหัวข้อ component, การ์ด KPI, หัวข้อกราฟ/ตาราง, badge และ chart tooltip

ระหว่างหาคำแปลที่สอดคล้องกับระบบ พบว่า `src/lib/labels.ts` (`STAGE_LABELS`) ซึ่งเป็น "single source of truth" ของสถานะดีล (`lead/qualified/proposal/negotiation/won/lost`) ที่ใช้ร่วมกันใน `SalesPage.tsx`, `CreateOpportunityDialog.tsx`, `ImpactOSPage.tsx` ก็ยังเป็นภาษาอังกฤษล้วนทั้งหมด — เป็นต้นตอที่แท้จริงของปัญหานี้ในระดับระบบ ไม่ใช่แค่สองไฟล์ที่กำลังแก้ แต่การแก้ต้นตอนั้นกระทบหน้า Sales Pipeline ที่ทีมขายใช้งานจริงทุกวัน ซึ่งอยู่นอกขอบเขตที่ขอให้ตรวจในรอบนี้

คำแปลทั้งหมดในเอกสารนี้ผ่านการหารือและยืนยันทีละจุดกับผู้ร้องขอแล้ว (ดูตาราง D1-D14 ใน Decisions)

## Goals / Non-Goals

**Goals:**
- ข้อความที่ผู้ใช้เห็นทั้งหมดใน `MarketingPage.tsx` และ `AttributionTab.tsx` เป็นภาษาไทย ยกเว้นคำที่ไม่มีบรรทัดฐานแปลในระบบอยู่แล้ว ("Ticket" — ดู D11)
- คำแปลที่เลือกใช้ต้องสอดคล้องกับบรรทัดฐานที่มีอยู่แล้วในระบบเท่าที่เป็นไปได้ (อัตราชนะ, ดีล) เพื่อลดความไม่ตรงกันข้ามหน้า
- หัวคอลัมน์ "อีเมล" ที่ป้ายกำกับผิดความหมายในแท็บ "ลูกค้า" ต้องสื่อความหมายตรงกับข้อมูลจริงที่แสดง
- คอลัมน์สัดส่วนรายได้ต้องมีตัวเลขให้อ่าน ไม่ใช่แท่งภาพเปล่า

**Non-Goals:**
- ไม่แก้ `src/lib/labels.ts` (`STAGE_LABELS`) หรือหน้าที่พึ่งพาค่านั้น — คงคำว่า "Lead/Qualified/Proposal/Negotiation/Won/Lost" ไว้ที่ `SalesPage.tsx`/`CreateOpportunityDialog.tsx`/`ImpactOSPage.tsx` ตามเดิม เป็นงานคนละ scope ที่ต้องมี regression testing ของตัวเอง
- ไม่เปลี่ยนโครงสร้าง/การจัดวางตาราง (จำนวนคอลัมน์, ลำดับ) ยกเว้นการเพิ่มตัวเลข % ในคอลัมน์สัดส่วนรายได้ตามที่ตกลงไว้
- ไม่เปลี่ยน backend/API — ข้อมูลที่ใช้คำนวณ % สัดส่วนมีอยู่แล้วในทุก response ปัจจุบัน

**Decision D6 — จำกัดขอบเขตไว้ที่ 2 ไฟล์ ไม่แก้ `src/lib/labels.ts`**
ทางเลือกที่พิจารณา: แก้ `STAGE_LABELS` ให้เป็นไทยจริง แล้วให้ทุกไฟล์ที่เกี่ยวข้อง (`AttributionTab.tsx` รวมถึง `SalesPage.tsx`, `CreateOpportunityDialog.tsx`, `ImpactOSPage.tsx`) อ้างอิงค่าเดียวกัน — ตัดออกในรอบนี้ เพราะกระทบหน้า Sales Pipeline ที่ทีมขายใช้งานจริงทุกวัน ซึ่งอยู่นอกขอบเขตที่ขอให้ตรวจ การรวมเข้ามาจะทำให้ regression surface ใหญ่กว่าที่ควรสำหรับงาน "แก้ label หน้าแคมเปญอีเมล" เพียงอย่างเดียว — ผลคือคำว่า "ดีลที่ชนะ"/"ลีด" ใน `AttributionTab.tsx` จะเป็น string อิสระเฉพาะไฟล์ ไม่ได้ผูกกับ `STAGE_LABELS` และจะไม่ตรงกับ badge "Won"/"Lead" ที่ยังคงเห็นบนหน้า Sales Pipeline จนกว่าจะมีการแก้ `labels.ts` แยกต่างหากในอนาคต

**Decision D9/D10 — คำสั้นในหัวตาราง ต่างจากคำเต็มใน KPI card**
ตารางทั้งสอง (`SourceTable`, `CampaignTable`) มี 8-9 คอลัมน์อยู่แล้วในพื้นที่จำกัด (`text-xs`, มี `overflow-x-auto`) จึงใช้คำสั้น ("ชนะ", "ลีด") ในหัวคอลัมน์ ส่วนการ์ด KPI มีพื้นที่มากกว่าจึงใช้คำเต็มที่สื่อความชัดกว่า ("ดีลที่ชนะ", "ลีดทั้งหมด") — เป็นรูปแบบเดียวกับที่ระบบทำอยู่แล้วในจุดอื่น (เช่น การ์ดสรุปในแท็บ "แคมเปญ" ของ `MarketingPage.tsx` ใช้คำเต็ม ส่วนหัวตารางในหน้าเดียวกันใช้คำสั้น)

**Decision D12 — เพิ่ม % บนคอลัมน์สัดส่วนรายได้**
เดิมคอลัมน์นี้เป็นแท่ง (`barPct`) แสดงสัดส่วนภาพอย่างเดียว ไม่มีตัวเลขกำกับ ทำให้ผู้ใช้ต้องกะขนาดแท่งด้วยตา — ข้อมูล `won_value` และ `maxValue` มีอยู่แล้วในการคำนวณ `barPct` ปัจจุบัน (`Math.min(100, r.won_value / maxValue * 100)`) จึงเพิ่มแค่การแสดงตัวเลขนี้เป็นข้อความควบคู่กับแท่ง ไม่ต้องเรียก API เพิ่มหรือเปลี่ยนโครงสร้างข้อมูล

## Risks / Trade-offs

- **[Risk] คำว่า "ดีลที่ชนะ"/"ลีด" ใน AttributionTab.tsx จะไม่ตรงกับ "Won"/"Lead" ที่ยังเป็นอังกฤษบนหน้า Sales Pipeline** (ผลจาก Decision D6) → **Mitigation:** เป็นการยอมรับความไม่ตรงกันชั่วคราวที่ทราบล่วงหน้าและตั้งใจ ไม่ใช่ผลข้างเคียงที่ไม่รู้ตัว — บันทึกไว้ใน Non-Goals และเสนอเป็น change แยกในอนาคตถ้าต้องการแก้ที่ต้นตอ
- **[Risk] Regression ต่อ test ที่มีอยู่** → ตรวจแล้วไม่มี test ใน `src/__tests__/` อ้างอิงสตริง "Attribution", "Templates", "Win Rate", "Leads", หรือ "Revenue Bar" จึงไม่คาดว่าจะพัง
- **[Risk] "แอตทริบิวชัน" (D5) และ "มาร์เก็ตติ้งแอตทริบิวชัน" (D8) เป็นคนละคำกัน** แม้จะอ้างถึง concept เดียวกัน (ชื่อแท็บ vs หัวข้อ component ที่แท็บนั้นพาไป) → **Mitigation:** ยืนยันกับผู้ร้องขอแล้วว่าความยาวต่างกันตามต้นฉบับภาษาอังกฤษที่ต่างกัน ("Attribution" vs "Marketing Attribution") เป็นรูปแบบที่ระบบมีอยู่แล้วในจุดอื่น (เช่น เมนูข้างใช้ชื่อสั้น "การตลาด" ขณะที่หน้าเต็มใช้ชื่อยาวกว่า "แคมเปญอีเมล")

## Migration Plan

1. แก้ `MarketingPage.tsx` (D1-D5) ก่อน — เป็นการแก้ label ล้วนๆ ไม่กระทบ state/logic ความเสี่ยงต่ำสุด
2. แก้ `AttributionTab.tsx` (D7-D14) รวมการเพิ่มตัวเลข % ในคอลัมน์สัดส่วนรายได้ (D12)
3. ไม่ต้องใช้ feature flag — เป็นการแก้ label ในรีลีสเดียว ไม่มี DB migration ไม่มี API change
4. Rollback: revert commit ที่เกี่ยวข้อง ไม่มีข้อมูลถูกทำลาย
