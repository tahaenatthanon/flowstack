## Why

ตัวอย่างอีเมลในหน้าแคมเปญมี 2 จุดที่เนื้อหาฝั่งขวาสามารถ "หายไป" เมื่อกรอบแสดงผลแคบกว่าความกว้างมาตรฐานของอีเมล (600px ตามธรรมเนียมอุตสาหกรรม HTML email):

1. **ไดอะล็อก "ดู" ของแท็บเทมเพลตหลัก** (`sm:max-w-3xl`) — ยืนยันด้วยการตรวจ DOM จริง: กรอบ preview กว้างแค่ ~599px เนื้อหาจริงต้องการ 640px ส่วนเกิน ~56px ต้อง**เลื่อนแนวนอนดู** ได้ก็จริง แต่ scrollbar เล็กมากจนสังเกตยาก ผู้ใช้ส่วนใหญ่ไม่รู้ว่ามีเนื้อหาซ่อนอยู่ฝั่งขวา
2. **แท็บ "ตัวอย่าง" ในไดอะล็อกสร้าง/แก้ไขแคมเปญ** — เนื้อหาที่พิมพ์เอง (ไม่ใช่ template เต็ม) ถูกครอบด้วย "การ์ด" ที่มี `max-width:600px` และ **`overflow:hidden`** (ใน `buildEmailPreviewHtml()`) ถ้าผู้ใช้แทรกตารางกว้างผ่านปุ่ม "ตาราง" ในตัวแก้ไข เนื้อหาส่วนเกิน 600px จะ**ถูกตัดทิ้งแบบไม่มี scrollbar ให้เลื่อนเลย** มองไม่เห็นถาวร ต่างจากจุดที่ 1 ที่อย่างน้อยยังเลื่อนดูได้

จุดที่ 2 รุนแรงกว่าจุดที่ 1 ชัดเจน (ตัดทิ้งถาวร vs. แค่ต้องเลื่อนดู) และเป็นปัญหาที่ถูกเลื่อนมาจาก change ก่อนหน้า (`fix-campaign-preview-template-double-wrap`) ซึ่งระบุไว้ชัดว่าอยู่นอกสโคปและต้องแก้แยกเป็น change นี้

## What Changes

- แก้ "การ์ด" ใน `buildEmailPreviewHtml()` ให้ใช้ `overflow-x:auto` แทน `overflow:hidden` — เนื้อหาที่กว้างเกิน 600px (เช่น ตารางที่ผู้ใช้แทรกเอง) จะเลื่อนดูได้เสมอ ไม่ถูกตัดทิ้งแบบมองไม่เห็นอีกต่อไป
- ขยายความกว้างของไดอะล็อก "ดู" ของแท็บเทมเพลตหลัก (`sm:max-w-3xl` → กว้างขึ้นพอที่จะรองรับ 600px + padding โดยไม่ต้องเลื่อนแนวนอนบนหน้าจอเดสก์ท็อปทั่วไป) เพื่อลดความถี่ที่ต้องเลื่อนดูตั้งแต่ต้น
- **นอกสโคป:** การทำ responsive scaling ให้เนื้อหา 600px ย่อพอดีจอมือถือ/หน้าต่างแคบมากๆ — ยอมรับว่าบนจอที่แคบจริงๆ (เช่น มือถือ) ยังต้องเลื่อนแนวนอนดูอยู่ดี (พฤติกรรมเดียวกับที่ email client จริงทำเมื่อเจอ HTML email กว้าง 600px) จุดสำคัญคือต้อง "เลื่อนดูได้เสมอ" ไม่ใช่ "หายไปเลย"

## Capabilities

### New Capabilities

- `email-campaign-preview-overflow`: กำหนดว่าพื้นที่แสดงตัวอย่างอีเมลทั้ง 2 จุด (ไดอะล็อก "ดู" ของแท็บเทมเพลต และแท็บ "ตัวอย่าง" ในไดอะล็อกสร้าง/แก้ไขแคมเปญ) ต้องไม่ตัดเนื้อหาที่กว้างเกินกรอบทิ้งแบบมองไม่เห็น — ต้องเลื่อนดูได้เสมอ และควรมีความกว้างพอที่จะไม่ต้องเลื่อนบนหน้าจอเดสก์ท็อปทั่วไป

### Modified Capabilities

(ไม่มี)

## Impact

- **ไฟล์ที่คาดว่าต้องแก้:** `src/pages/CampaignsPage.tsx` — ฟังก์ชัน `buildEmailPreviewHtml()` (การ์ด `overflow:hidden` → `overflow-x:auto`) และ `className` ของ `DialogContent` ในไดอะล็อก "ดู" ของแท็บเทมเพลตหลัก
- **ผลกระทบ:** เฉพาะการแสดงผลในหน้าแคมเปญอีเมล (ไดอะล็อก "ดู" template + แท็บ "ตัวอย่าง") ไม่กระทบอีเมลจริงที่ส่งออกไป ไม่มี database migration ไม่มี breaking change ต่อ API
