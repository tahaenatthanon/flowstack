## Why

Widget "สถานะช่องทาง" ในแดชบอร์ดคอนเทนต์ (`ContentDashboardPage`) ปัจจุบันแสดงสถานะของแต่ละช่องทางเพียง "จุดสี" (เขียว = active, เทา = inactive) โดยไม่มีข้อความระบุสถานะที่ชัดเจน ทำให้ผู้ใช้ไม่สามารถทราบได้ทันทีว่าช่องทางนั้น "ใช้งานอยู่" หรือ "ไม่ใช้งาน" จริง ๆ และการแสดงผลอิงจาก `is_active` ซึ่งถูกตั้งเป็นค่าเริ่มต้น `1` ตอนสร้างช่องทาง (hardcode ใน `brand-content.php`) — ผู้ใช้จึงมองไม่ออกว่าสถานะที่เห็นเป็นสถานะจริงที่ถูกตั้งไว้ในระบบหรือไม่

## What Changes

- เอา Status Badge รูปแบบเดิม (จุดสี) ออก แล้วย้าย Status ไปแสดงไว้ด้านหลังข้อมูลของแต่ละช่องทาง
- ปรับการตรวจสอบสถานะการเชื่อมต่อให้ตรวจสอบจากการเชื่อมต่อจริงกับช่องทาง (reuse logic ของ `test-channel` ที่ทำ cURL/API call จริง) — ไม่ใช้เพียงค่า `is_active` เป็นตัวบอกสถานะ
- แสดง Label ตามผลการเชื่อมต่อจริง: เชื่อมต่อได้จริง → "เชื่อมต่อแล้ว" (สีเขียว), เชื่อมต่อไม่ได้หรือการเชื่อมต่อไม่สมบูรณ์ → "ไม่เชื่อมต่อ" (สีแดง)
- แสดงสถานะด้วย "จุดสี + ข้อความ" (colored dot + label) โดยไม่ต้องมีพื้นหลังหรือ Status Badge — จุดสีสะท้อนผลการเชื่อมต่อจริง (เขียว/แดง) และข้อความระบุสถานะชัดเจน
- Status และ Label แสดงในรูปแบบเดียวกันและสอดคล้องกับ UI ของระบบ
- สถานะและสีที่แสดงสะท้อนสถานะการเชื่อมต่อจริงของแต่ละช่องทาง (ไม่ hardcode/mock)

### Modified Capabilities

- `content-dashboard-schedule-channels`: widget "สถานะช่องทาง" เอา Status Badge เดิม (จุดสี) ออก และย้าย Status ไปแสดงด้านหลังข้อมูล พร้อมแสดง "จุดสี + ข้อความ" (ไม่มีพื้นหลัง/Status Badge) — "เชื่อมต่อแล้ว" เขียว / "ไม่เชื่อมต่อ" แดง — ตามผลการเชื่อมต่อจริง (ไม่ใช่แค่ `is_active`)

## Impact

- `api/brand-content.php` — เพิ่ม action สำหรับตรวจสอบสถานะการเชื่อมต่อจริงแบบ batch (reuse logic `test-channel` → helper) คืน `ok` ต่อ channel
- `src/hooks/useContent.ts` — เพิ่ม hook สำหรับดึงสถานะการเชื่อมต่อจริง (หรือรวมใน `usePublishChannels`)
- `src/pages/ContentDashboardPage.tsx` — เอา Status Badge (จุดสี) เดิมออก, แสดง "จุดสี + ข้อความ" (ไม่มีพื้นหลัง/Status Badge) ("เชื่อมต่อแล้ว" เขียว / "ไม่เชื่อมต่อ" แดง) ตามผลการเชื่อมต่อจริง
- ไม่กระทบ DB หรือ logic การคำนวณใดๆ
