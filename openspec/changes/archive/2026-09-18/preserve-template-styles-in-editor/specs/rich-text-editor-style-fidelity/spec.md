## ADDED Requirements

### Requirement: ตัวแก้ไขต้องคงสไตล์ของตาราง (table/tr/td/th) ไว้หลังแก้ไขเนื้อหา
`ArticleEditor` SHALL คง `style` attribute แบบ inline ที่ผูกอยู่กับ `<table>`, `<tr>`, `<td>`, `<th>` ไว้ครบถ้วน ทั้งตอน parse เนื้อหาเข้ามาครั้งแรกและตอน re-serialize กลับเป็น HTML ทุกครั้งที่ผู้ใช้แก้ไขเนื้อหา

#### Scenario: แก้ข้อความในตารางที่มีสีพื้นหลัง แล้วสีไม่หาย
- **WHEN** ผู้ใช้พิมพ์แก้ไขข้อความในส่วนที่อยู่ภายใน `<td>` ที่มี `style="background-color:..."`
- **THEN** เนื้อหา HTML ที่ได้จากตัวแก้ไข (`editor.getHTML()`) ยังคงมี `style="background-color:..."` บน `<td>` นั้นอยู่ครบ ไม่ถูกตัดทิ้ง

#### Scenario: แก้ข้อความในส่วนอื่นของเอกสาร ตารางที่ไม่ได้แก้ก็ยังคงสไตล์ไว้
- **WHEN** ผู้ใช้แก้ไขข้อความในส่วนหนึ่งของเนื้อหา ขณะที่มีตารางอื่นที่มี inline style อยู่ในเอกสารเดียวกันแต่ไม่ได้ถูกแก้ไข
- **THEN** ตารางที่ไม่ได้ถูกแก้ไขยังคง `style` attribute เดิมไว้ครบถ้วนเช่นกัน

### Requirement: ตัวแก้ไขต้องคงสไตล์ของหัวข้อ (h1-h4) ไว้หลังแก้ไขเนื้อหา
`ArticleEditor` SHALL คง `style` attribute แบบ inline ที่ผูกอยู่กับ heading ระดับ 1 ถึง 4 (`<h1>`-`<h4>`) ไว้ครบถ้วน ทั้งตอน parse เนื้อหาเข้ามาครั้งแรกและตอน re-serialize กลับเป็น HTML ทุกครั้งที่ผู้ใช้แก้ไขเนื้อหา

#### Scenario: แก้ข้อความในหัวข้อที่กำหนดสีตัวอักษรไว้ แล้วสีไม่หาย
- **WHEN** ผู้ใช้พิมพ์แก้ไขข้อความภายใน `<h1>` (หรือ h2-h4) ที่มี `style="color:..."`
- **THEN** เนื้อหา HTML ที่ได้จากตัวแก้ไขยังคงมี `style="color:..."` บน heading นั้นอยู่ครบ ไม่ถูกตัดทิ้ง

### Requirement: ตัวแก้ไขต้องรองรับ `<div>` พร้อมสไตล์ของมันไว้หลังแก้ไขเนื้อหา
`ArticleEditor` SHALL รองรับ element `<div>` เป็น block node ในเนื้อหาที่แก้ไขได้ พร้อมคง `style` attribute แบบ inline ของมันไว้ ทั้งตอน parse เนื้อหาเข้ามาครั้งแรกและตอน re-serialize กลับเป็น HTML ทุกครั้งที่ผู้ใช้แก้ไขเนื้อหา

#### Scenario: แก้ข้อความในเนื้อหาที่มี div ตกแต่งอยู่ แล้ว div ไม่หายไป
- **WHEN** เนื้อหาที่โหลดเข้าตัวแก้ไขมี `<div style="display:flex;...">` (เช่น วงกลมไอคอนตกแต่งของ template หรูหราสีม่วง) และผู้ใช้แก้ไขข้อความส่วนอื่นในเอกสารเดียวกัน
- **THEN** เนื้อหา HTML ที่ได้จากตัวแก้ไขยังคงมี `<div style="display:flex;...">` อยู่ครบ ไม่ถูกตัดทิ้งหรือ unwrap กลายเป็นข้อความเปล่า

### Requirement: การเพิ่มการรองรับ style ต้องไม่กระทบเนื้อหาบทความเดิมที่ไม่มีสไตล์เหล่านี้
เนื่องจาก `ArticleEditor` ถูกใช้ร่วมกันทั้งในไดอะล็อกแคมเปญอีเมลและไดอะล็อกเนื้อหาบทความ การเพิ่มการรองรับ `style`/`<div>` ตาม requirement ข้างต้น SHALL ไม่เปลี่ยนแปลงพฤติกรรมของเนื้อหาบทความที่ไม่มี inline style หรือ `<div>` เหล่านี้อยู่แล้ว

#### Scenario: บทความปกติที่ไม่มี inline style ยังทำงานเหมือนเดิม
- **WHEN** ผู้ใช้แก้ไขเนื้อหาบทความทั่วไปในไดอะล็อกเนื้อหา (ไม่มี `<table>`/`<div>` ที่มี inline style)
- **THEN** พฤติกรรมการแก้ไข/บันทึกเนื้อหาเป็นไปตามปกติเหมือนก่อนการเปลี่ยนแปลงนี้ ไม่มีผลข้างเคียงที่สังเกตเห็นได้
