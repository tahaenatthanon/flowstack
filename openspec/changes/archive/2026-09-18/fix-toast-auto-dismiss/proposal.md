## Why

ผู้ใช้รายงานว่าหลังเลือกคอนเทนต์ในหน้าต่าง "ดึงคอนเทนท์" (toast "นำเข้าบทความแล้ว") toast ที่ควรจะหายไปเองกลับค้างอยู่บนหน้าจอไม่หาย ตรวจสอบโค้ด `@radix-ui/react-toast` (ที่ `useToast`/`toaster.tsx` ใช้เป็นฐาน) พบ 2 ปัญหาประกอบกัน:

1. **Radix pause-on-hover ครอบคลุมทั้ง viewport ไม่ใช่แค่ตัว toast** — Radix ผูก event `pointermove` ไว้ที่ wrapper ของ `ToastViewport` ทั้งกล่อง (ไม่ใช่แค่การ์ด toast ใบเดียว) ทุกครั้งที่เมาส์ขยับอยู่ในโซนนั้นจะ pause auto-dismiss timer ของทุก toast ทันที และ resume ก็ต่อเมื่อเมาส์ออกจากทั้ง viewport เท่านั้น เนื่องจาก `ToastViewport` วางอยู่มุมขวาล่างและ dialog "สร้างแคมเปญใหม่" ที่เปิดขึ้นทันทีหลังเลือกคอนเทนต์มีพื้นที่ทับซ้อนกับโซนนี้ การขยับเมาส์ตามปกติของผู้ใช้ในฟอร์มนั้น (เช่น เลื่อนดู template) จึงกวาดผ่านโซน toast viewport ซ้ำๆ ทำให้ timer ไม่เคยเดินจบเลย
2. **ไม่มี fallback ที่ไม่ขึ้นกับ pause** — `dismiss()` ใน `use-toast.ts` ถูกเรียกได้ทางเดียวคือผ่าน `onOpenChange(false)` ของ Radix ซึ่งมาจาก timer ที่ pause ได้ตามข้อ 1 เท่านั้น ไม่มี timer อิสระใดๆ ที่รับประกันว่า toast จะหายภายในเวลาที่กำหนดแน่นอนไม่ว่าเมาส์จะอยู่ตรงไหน — ค่า `TOAST_REMOVE_DELAY = 1000000` (≈16.7 นาที) ที่ตั้งไว้ผิดยิ่งซ้ำเติมปัญหา (เป็นค่า placeholder เดิมจาก shadcn-ui boilerplate) แต่ถึงจะแก้ค่านี้อย่างเดียวก็ยังไม่พอ เพราะ cleanup timer นั้นเองก็ยังต้องรอ `dismiss()` ถูกเรียกก่อน ซึ่งติดปัญหาข้อ 1 อยู่ดี

`useToast` เป็น hook กลางที่ใช้ร่วมกันทั้งระบบ ไม่ใช่บั๊กเฉพาะจุดใดจุดหนึ่ง — แก้ที่นี่ที่เดียวจะแก้ปัญหาให้ toast ทุกจุดในแอปพร้อมกัน

## What Changes

- เพิ่ม timer อิสระใน `toast()` (`src/hooks/use-toast.ts`) ที่เรียก `dismiss()` โดยตรงหลังผ่านไปเวลาที่กำหนด (5000 มิลลิวินาที) — timer นี้ไม่ผูกกับกลไก pause-on-hover ของ Radix จึงรับประกันว่า toast จะเริ่ม dismiss ภายในเวลาที่แน่นอนเสมอ ไม่ว่าเมาส์ผู้ใช้จะอยู่ตรงไหน
- ลดค่า `TOAST_REMOVE_DELAY` จาก `1000000` เป็น `1000` มิลลิวินาที เพื่อให้ state cleanup (ลบ toast ออกจาก array จริงๆ หลัง dismiss) เกิดขึ้นเร็วพอ ไม่ทิ้ง timer ค้างนาน 16 นาทีโดยไม่จำเป็น

## Capabilities

### New Capabilities
- `toast-notification-lifecycle`: กำหนดพฤติกรรมการแสดงและหายไปของ toast notification ทั่วทั้งระบบ (auto-dismiss, fallback cleanup)

### Modified Capabilities
(ไม่มี)

## Impact

- **Frontend**: `src/hooks/use-toast.ts` เท่านั้น (เพิ่ม timer อิสระในฟังก์ชัน `toast()` + เปลี่ยนค่าคงที่ 1 ตัว ไม่มี logic อื่นเปลี่ยน)
- **ผลกระทบวงกว้าง**: hook นี้ใช้ร่วมกันทุกจุดที่เรียก `toast()` ทั่วแอป (ไม่ใช่แค่ `PullFromContentDialog.tsx`) — การแก้นี้ทำให้ toast ทุกจุดในระบบหายไปภายในเวลาที่แน่นอนเสมอ ไม่มีจุดใดที่ต้องพึ่งพาพฤติกรรมค้างนานแบบเดิม
- ไม่มี DB/API เปลี่ยนแปลง — ย้อนกลับได้ทันทีด้วย git revert ไฟล์เดียว
