## Why

หลังตัดหัวข้อกำกับคอลัมน์ "ต้องดำเนินการ"/"ภาพรวม" ออกจากแท็บภาพรวมของแดชบอร์ดคอนเทนต์ ([content-dashboard-row-layout] สืบเนื่องจาก `simplify-content-dashboard-overview`) โครง 2 คอลัมน์เดิม (ซ้าย 2/3 = เผยแพร่ล้มเหลว+คอนเทนต์รอดำเนินการ, ขวา 1/3 = ความคืบหน้าการผลิต+คิวเผยแพร่+กำหนดการโพสต์ถัดไป+เนื้อหาล่าสุด) เผยปัญหาที่เคยถูกป้ายกำกับกลบไว้: วัดความสูงจริงในเบราว์เซอร์ (จอ 1440px, ข้อมูลจริงของ tenant) พบว่าคอลัมน์ซ้าย (กว้างกว่า) สูงรวมแค่ 728px ขณะคอลัมน์ขวา (แคบกว่า) สูงถึง 1425px — เพราะ CSS Grid บังคับทั้งแถวสูงเท่ากับคอลัมน์ที่สูงที่สุด คอลัมน์ซ้ายจึงเหลือพื้นที่ว่างเปล่าท้ายคอลัมน์ยาวเกือบ 700px ที่มองเห็นได้ชัดเจนในเบราว์เซอร์จริง

รากของปัญหาคือใช้ "โครง 2 คอลัมน์ก้อนเดียว" ครอบทั้ง 6 การ์ด ทั้งที่การ์ดแต่ละใบมีความสูงต่างกันมาก (135px–650px) และไม่มีเหตุผลให้ต้องอยู่ในคอลัมน์เดียวกันตลอดทั้งหน้าอีกต่อไป (การจัดกลุ่มตามความหมาย "เร่งด่วน vs อ้างอิง" ที่เคยมีป้ายกำกับก็ไม่จำเป็นแล้วเช่นกัน) — แนวทางแก้คือทำตามรูปแบบที่ `HomePage.tsx` ใช้อยู่แล้วทั้งหน้า: แบ่งเป็นหลายแถวอิสระต่อกัน แต่ละแถวเลือกอัตราส่วนคอลัมน์ของตัวเอง (1:1 หรือ 2:1) ตามคู่การ์ดที่จับคู่กันในแถวนั้น ไม่ผูกความสูงข้ามแถว

## What Changes

- เปลี่ยนโครงแท็บภาพรวมจาก "2 คอลัมน์ก้อนเดียวครอบทั้ง 6 การ์ด" เป็น **3 แถวอิสระ** โดยแต่ละแถวจับคู่การ์ด 2 ใบตามความสูงจริงที่วัดได้ (คำนวณจากทุกวิธีจับคู่ที่เป็นไปได้ เลือกชุดที่ผลรวมส่วนต่างความสูงต่ำที่สุด):
  - **แถว 1** (`lg:grid-cols-2`, 1:1): เผยแพร่ล้มเหลว + คอนเทนต์รอดำเนินการ (ส่วนต่าง ~28px)
  - **แถว 2** (`lg:grid-cols-3` col-span-2, 2:1): เนื้อหาล่าสุด (กว้าง) + ความคืบหน้าการผลิต (แคบ) (ส่วนต่าง ~244px — มากที่สุดในสามแถว แต่ยังกักอยู่ในแถวเดียว ไม่ลามไปแถวอื่น)
  - **แถว 3** (`lg:grid-cols-2`, 1:1): คิวเผยแพร่ + กำหนดการโพสต์ถัดไป (ส่วนต่าง ~27px)
- ตัดโครง `grid grid-cols-1 xl:grid-cols-3 gap-6` (คอลัมน์ก้อนเดียว) และ `xl:col-span-2`/`col-span-1` เดิมออกทั้งหมด แทนที่ด้วย breakpoint `lg` (ให้ตรงกับ pattern แถวใน `HomePage.tsx` ที่ใช้ `lg:grid-cols-2`/`lg:grid-cols-3` ไม่ใช่ `xl`)
- คงตัว "คอลัมน์ต้องดำเนินการแสดงข้อความว่างรวม" (จาก `simplify-content-dashboard-overview`) ไว้ แต่ปรับให้ครอบเฉพาะแถว 1 (เผยแพร่ล้มเหลว + คอนเทนต์รอดำเนินการ) ซึ่งเป็นคู่เดิมที่เคยอยู่คอลัมน์ "ต้องดำเนินการ" พอดี — พฤติกรรม (แสดงข้อความว่างรวมเมื่อทั้งคู่ไม่มีรายการ) ไม่เปลี่ยน แค่ตำแหน่งเปลี่ยนจาก "คอลัมน์ซ้ายทั้งคอลัมน์" เป็น "แถว 1 ทั้งแถว"
- **BREAKING** (การแสดงผล ไม่ใช่ข้อมูล): ลำดับการ์ดที่เห็นตอน stack บนจอแคบ (ต่ำกว่า `lg`) เปลี่ยนจาก `เผยแพร่ล้มเหลว, คอนเทนต์รอดำเนินการ, ความคืบหน้าการผลิต, คิวเผยแพร่, กำหนดการโพสต์ถัดไป, เนื้อหาล่าสุด` เป็น `เผยแพร่ล้มเหลว, คอนเทนต์รอดำเนินการ, เนื้อหาล่าสุด, ความคืบหน้าการผลิต, คิวเผยแพร่, กำหนดการโพสต์ถัดไป` (เนื้อหาล่าสุดขยับขึ้นมาอยู่แถว 2 คู่กับความคืบหน้าการผลิต)
- Breakpoint ที่สลับจาก stacked เป็นหลายคอลัมน์เปลี่ยนจาก `xl` (1280px) เป็น `lg` (1024px) ให้ตรงกับ `HomePage.tsx` — จอขนาด 1024–1279px จะเห็นเป็นหลายคอลัมน์เร็วขึ้นกว่าเดิม

## Capabilities

### New Capabilities
_(ไม่มี — ปรับโครง layout ของ capability ที่มีอยู่แล้วเท่านั้น)_

### Modified Capabilities
- `content-dashboard-layout`: เปลี่ยนจาก master layout 2 คอลัมน์ก้อนเดียว (`xl:col-span-2`/`col-span-1`) เป็น 3 แถวอิสระ อัตราส่วนต่อแถว (1:1, 2:1, 1:1) ที่ breakpoint `lg`; ปรับขอบเขตของ requirement ข้อความว่างรวมให้ครอบเฉพาะแถว 1

## Impact

- **Affected code**: `src/pages/ContentDashboardPage.tsx` เท่านั้น (จัดเรียง JSX ของการ์ดทั้ง 6 ใบใหม่เป็น 3 แถว, ไม่แตะ logic การคำนวณข้อมูลใดๆ — `actionColumnEmpty`, `hasFailures`, `hasAgingItems` ยังใช้ชื่อ/ค่าเดิม แค่ขอบเขตการใช้ (scope) แคบลงเหลือแค่แถว 1)
- **ไม่กระทบ backend**: ไม่มีการเปลี่ยนแปลง API/query ใดๆ
- **ไม่กระทบ**: แท็บ "วิเคราะห์" และ capability อื่นทั้งหมดที่ไม่เกี่ยวกับ layout ของแท็บภาพรวม
- **สมมติฐาน**: ตัวเลขความสูง (338/366/406/135/162/650px) มาจากการวัดจริง 1 ครั้งกับข้อมูล tenant ปัจจุบัน ณ วันที่สำรวจ — อาจไม่ตรงเป๊ะกับทุก tenant/ทุกช่วงเวลา แต่การจัดเป็น "หลายแถวอิสระ" ทำให้ความเสี่ยงจากตัวเลขคลาดเคลื่อนถูกจำกัดอยู่แค่ในแถวนั้นๆ ไม่ลามทั้งหน้าเหมือนโครงเดิม จึงทนทานต่อความคลาดเคลื่อนได้ดีกว่าการยึดตัวเลขที่วัดได้แบบตายตัว
