## Why

ส่วน "Template เริ่มต้น" ในไดอะล็อกสร้าง/แก้ไขแคมเปญอีเมล (`MarketingPage.tsx`) ซ้อนอยู่ในคอลัมน์แคบ (ครึ่งหนึ่งของ grid 2 คอลัมน์ร่วมกับการ์ด "ผู้รับ") ทำให้แถบเลือก template แบบเลื่อนแนวนอนตกขอบ/ล้นออกนอกไดอะล็อกในบางสภาพหน้าจอ (ไม่เคลิป/ไม่เลื่อนได้จริง เพราะ CSS Grid item ไม่ยอมหดตัวต่ำกว่าความกว้างเนื้อหาโดยไม่มี `min-w-0`) และผู้ใช้ต้องเลื่อนดู 20 template ทีละไม่กี่อันแม้จอกว้างแค่ไหนก็ตาม เพราะถูกจำกัดด้วยความกว้างครึ่งคอลัมน์เสมอ

นอกจากนี้ เมื่อเลือก template ไปแล้วเปลี่ยนใจ ผู้ใช้ไม่มีทางยกเลิกการเลือกเพื่อกลับไปเขียนเนื้อหาเองตั้งแต่ต้น ต้องปิดไดอะล็อกแล้วเปิดใหม่เท่านั้น

## What Changes

- ย้าย "Template เริ่มต้น" ออกจากการ์ด "ผู้รับ" (คอลัมน์แคบ) มาเป็น section เดี่ยวเต็มความกว้างไดอะล็อก ต่อจากแถว ผู้ส่ง/ผู้รับ (เลข badge ของ section ขยับ: Template เริ่มต้น = ②③④→④ ใหม่ ส่วน "เนื้อหาอีเมล" ขยับจาก ④ เป็น ⑤)
- เปลี่ยนแถบเลือก template จากเลื่อนแนวนอน (`ScrollableKanban`, มีปัญหา overflow) เป็น grid ห่อบรรทัด (wrap) แสดงครบทั้ง 20 template โดยไม่ต้องเลื่อน
- เพิ่มพฤติกรรม toggle การเลือก template: คลิก template ที่เลือกอยู่ซ้ำอีกครั้ง = ยกเลิกการเลือก
- การยกเลิกการเลือก (deselect) จะล้างเนื้อหาอีเมล (`campaignBody`) กลับเป็นค่าว่าง แต่ต้องผ่าน confirm dialog ก่อนเสมอ (ป้องกันล้างเนื้อหาที่แก้ไขต่อจาก template โดยไม่ตั้งใจ)

## Capabilities

### New Capabilities
- `email-campaign-template-picker`: พฤติกรรมและ layout ของส่วนเลือก template เริ่มต้นในไดอะล็อกแคมเปญอีเมล — ตำแหน่ง/การจัดวางแบบเต็มความกว้างไม่มี scroll, และการ toggle เลือก/ยกเลิกเลือกพร้อม confirm dialog ก่อนล้างเนื้อหา

### Modified Capabilities
(ไม่มี — ไม่กระทบ requirement ของ `email-campaign-recipient-resolution` หรือ `multi-select-combobox` ที่มีอยู่ เพราะเป็นแค่ตำแหน่ง/UI ของส่วน template ซึ่งไม่เคยถูกกำหนดสเปคไว้มาก่อน)

## Impact

- `src/pages/MarketingPage.tsx`: ปรับ JSX ส่วนไดอะล็อกสร้าง/แก้ไขแคมเปญ (section ผู้รับ, section template ใหม่, เลข badge ของ section เนื้อหาอีเมล), เพิ่ม handler `onClick` แบบ toggle พร้อมเรียก `useConfirm()` (มีอยู่แล้วในไฟล์นี้), เปลี่ยนจาก `ScrollableKanban` เป็น `flex flex-wrap` (หรือเทียบเท่า) สำหรับปุ่ม template
- ไม่กระทบ backend (`api/email-campaigns.php`) หรือ schema ฐานข้อมูล — เป็นการเปลี่ยนแปลงฝั่ง UI ล้วน
- ผลพลอยได้: แก้บั๊ก "ตกขอบ" ของ Template เริ่มต้น โดยอัตโนมัติ เพราะย้ายออกจากคอลัมน์แคบที่เป็นต้นเหตุ
